# opencode config

Portable, version-controlled configuration for [opencode](https://opencode.ai):
global config, agents, skills, and MCP server definitions. It is synced to a
**private GitHub repository** (`https://github.com/oasrcode/opencode-config`).
Secrets are excluded from version control, and credentials must never be
committed.

## What's inside

| Path                | Purpose                                                        |
| ------------------- | -------------------------------------------------------------- |
| `opencode.jsonc`    | Global config: models, MCP servers, compaction, default agent.  |
| `AGENTS.md`         | Global agent rules (graph-first discovery, delegation, safety). |
| `agents/*.md`       | Subagents: backend, devops, frontend, orchestrator, researcher, reviewer. |
| `skills/`           | Skills auto-loaded from `~/.config/opencode/skills`.            |
| `.skill-lock.json`  | Installed-skill lockfile (source + hash tracking).             |
| `install.sh`        | Idempotent bootstrap for a new machine.                        |

`package.json` and `package-lock.json` are **auto-generated by opencode**: it
creates them with its own pinned plugin dependency and installs plugin
dependencies itself at startup. They are therefore **not tracked** in this repo
(see `.gitignore`); do not commit or hand-edit them.

Model IDs in `opencode.jsonc` (for example `opencode-go/mimo-v2.5`) are
**provider-managed and not pinnable**: the provider may rename, retier, or
retire them independently of this repo. If a model becomes unavailable, update
the IDs in `opencode.jsonc` — nothing in `install.sh` depends on them.

## Clone onto a new WSL machine

This repository is **private**, so cloning on a new machine requires
authentication. Either log in with the GitHub CLI first (`gh auth login`), or,
when cloning over HTTPS, enter a **Personal Access Token (PAT)** as the
password when prompted — GitHub no longer accepts account passwords for Git
operations. The PAT needs at least read access to the repository.

If `~/.config/opencode` does **not** exist yet:

```bash
gh auth login                    # once per machine, if not already authenticated
git clone https://github.com/oasrcode/opencode-config.git ~/.config/opencode
cd ~/.config/opencode && ./install.sh
```

If it already exists, clone to a temp dir and copy only the working files in —
never nest a second `.git` inside `~/.config/opencode`:

```bash
git clone https://github.com/oasrcode/opencode-config.git /tmp/opencode-config
mkdir -p ~/.config/opencode
# Option A: rsync (not always installed on a fresh WSL)
rsync -a --exclude .git /tmp/opencode-config/ ~/.config/opencode/
# Option B: portable fallback if rsync is unavailable
# cp -a /tmp/opencode-config/. ~/.config/opencode/
# rm -rf ~/.config/opencode/.git
cd ~/.config/opencode && ./install.sh
```

## Bootstrap

```bash
cd ~/.config/opencode
./install.sh
```

`install.sh` is idempotent. It:

1. Replaces the `__HOME__` placeholder in `opencode.jsonc` with the real
   `$HOME` (one-time, with a `opencode.jsonc.bak.<timestamp>` backup).
2. If `~/.agents/skills` exists as a real directory, moves it to
   `~/.agents/skills.bak.<timestamp>` so the repo's `skills/` becomes the
   single source of truth (avoids duplicate skills loading). Symlinks or an
   absent directory are left untouched.
3. Prints non-fatal preflight hints if the MCP binary, Playwright browsers, or
   the `handoff` skill's `gitleaks`/`pre-commit` tools are missing (it never
   installs them for you and never fails on absence).

Plugin dependencies are handled by opencode itself at startup; `install.sh`
does not install them.

## MCP: `codebase-memory-mcp`

`codebase-memory-mcp` is **not** versioned in this repo — only its launch path is
referenced (`~/.local/bin/codebase-memory-mcp`). Install it per machine with:

```bash
curl -fsSL https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.sh | bash
```

> **Caution:** `curl … | bash` executes remote code with your user's privileges.
> Before running it, review the script (`curl -fsSL <url> | less`) or download and
> inspect it, so you know exactly what is being installed.

This places the binary at `~/.local/bin/codebase-memory-mcp`. `install.sh` warns
(but does not install) if it is missing.

Playwright browsers are also machine-local; install them with:

```bash
npx playwright install chromium
```

## Handoff skill: prerequisites per machine

The global `handoff` skill keeps durable, **git-committed** project memory in
each project — `docs/HANDOFF.md`, ADRs under `docs/adr/`, and a root
`CONTEXT.md` glossary — and ships a `templates/pre-commit-config.yaml` with a
`gitleaks` hook. The hook runs on **every commit** and scans the full staged
index (not only documentation), so secret patterns are caught before they are
committed. It needs two tools on the machine and one setup step per clone.

### Per machine

| Tool         | Install                                                                  |
| ------------ | ------------------------------------------------------------------------ |
| `gitleaks`   | `brew install gitleaks`, or a binary from the [releases page](https://github.com/gitleaks/gitleaks/releases). |
| `pre-commit` | `pipx install pre-commit` or `pip install --user pre-commit`.            |

The hook is declared with `id: gitleaks-system` and `language: system`, so it
consumes whatever `gitleaks` binary is already on your `PATH`. `gitleaks` is
MIT-licensed and distributed as a single self-contained binary — **no Go
toolchain is required**.

The shipped hook **must** set `pass_filenames: false`. Upstream's
`gitleaks-system` hook does not set it, and without it `pre-commit` appends
every staged filename to the command, while `gitleaks git` accepts at most one
argument — so any commit that stages more than one file would fail.

### Per project

In each project that adopts the template, copy the skill's
`templates/pre-commit-config.yaml` into the project root as
`.pre-commit-config.yaml` (the filename `pre-commit` expects) and **commit it
(with your approval)** to the project, then install the git hook **once per
clone**:

> **Do not overwrite an existing project `.pre-commit-config.yaml`.** If the
> project already has one, append the `gitleaks` hook entry from the template
> instead of replacing the file, so existing hooks are preserved.

Only when the project has no config yet:

```bash
# Guarded so an existing config is never overwritten.
[ -f .pre-commit-config.yaml ] || cp ~/.config/opencode/skills/handoff/templates/pre-commit-config.yaml .pre-commit-config.yaml
pre-commit install
```

Run `pre-commit install` only once `gitleaks` (>= 8.19) is installed and on your
`PATH`; otherwise the hook cannot run and every commit will fail.

`install.sh` warns (but does not install) if `gitleaks` or `pre-commit` is
missing, consistent with how it handles `codebase-memory-mcp` and Playwright
browsers.

## Re-authenticate

Credentials are never versioned. On each new machine:

```bash
opencode auth login
```

Then **quit and restart** opencode so the new config, agents, and skills load.

## Intentionally NOT versioned

- `auth.json` — credentials.
- `*.db`, `*.db-shm`, `*.db-wal` — local state databases.
- `package.json`, `package-lock.json`, `bun.lock` — auto-generated by opencode.
- `node_modules/` — auto-installed by opencode from its generated manifest.
- `log/`, `*.log` — runtime logs.
- `.opencode/` — local plans/scratch.
- `*.bak`, `*.bak.*` — install-time backups.

## Skills: single source of truth

`skills/` in this repo is the **only** source of skills. It is auto-loaded from
`~/.config/opencode/skills`. Do not keep a second copy under `~/.agents/skills`
on any machine, or skills will load twice.

A skill manager (e.g. one that installs into `~/.agents/skills`) may recreate
that directory after `install.sh` has demoted it. If it does, skills will
duplicate: re-run `./install.sh` to demote it again, or point the manager at
this repo's `skills/` so it does not create a second copy.

## Updating

After `install.sh` runs, `opencode.jsonc` becomes **locally modified** on
purpose: the tracked file keeps the `__HOME__` placeholder while the working copy
holds the real path. Discard that substitution before pulling, then re-apply it:

```bash
cd ~/.config/opencode
git checkout -- opencode.jsonc   # discard local __HOME__ substitution
git pull --ff-only
./install.sh                     # re-apply substitution
```

The `__HOME__` substitution and skills demotion make re-running `install.sh` a
no-op when the machine state is already correct.
